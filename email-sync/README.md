# 163 招聘邮件同步到飞书流程记录

该服务每次执行会只读连接 163 邮箱，通过 DeepSeek 提取招聘流程信息，并新增或更新飞书多维表格的「流程记录」。程序不删除邮件，也不改变邮件已读状态。

## 安全边界

- `.env` 只保存在本机且已被 Git 忽略。
- 163 邮箱使用客户端授权码，不使用登录密码。
- SQLite 只保存邮件 ID、标题、处理状态和飞书记录 ID，不保存邮件正文。
- 日志不输出 API Key、授权码和 App Secret。
- `复盘记录`、`自我评价`和`对应投递`永远不会被程序修改。

## 命令

在本目录运行：

```powershell
python main.py check
python main.py init
python main.py status
python main.py test-ai
python main.py run-once
```

- `check`：验证 163、DeepSeek 和飞书连接，并只输出非敏感诊断结果。
- `init`：记录当前最新邮件 UID，确保历史邮件不会被导入。
- `status`：显示最近邮件的处理状态及对应飞书记录，不显示任何密钥。
- `test-ai`：使用不含真实个人信息的合成面试邮件测试结构化提取，不写入飞书。
- `run-once`：处理初始化以后收到的新邮件。

首次部署务必先运行 `check`，再运行 `init`。之后再发送验收邮件。

## 飞书字段

必要字段均须为文本：`流程名称`、`公司`、`岗位名称`。

程序会自动发现并按类型写入这些可选字段：

`会议或测评链接`、`后续动作`、`备注`、`完成时间`、`当前状态`、`环节类型`、`环节结果`、`考察内容`、`计划时间`、`进行方式`、`面试轮次`、`邮件唯一ID`、`邮件主题`、`邮件发件人`、`邮件收取时间`、`AI置信度`、`识别状态`、`邮件摘要`。

模型返回的单选值必须与表格现有选项相同或能通过内置别名安全映射，否则该字段留空，不会自动创建新选项。

## 定时执行

确认手动同步成功后，在 PowerShell 中运行：

```powershell
.\install-task.ps1
```

任务默认每 5 分钟执行一次，禁止并行实例，单次最长运行 4 分钟。脚本创建系统任务前应先确保 `.env` 已填写并完成 `init`。

## 去重与更新

- SQLite 使用邮件 `Message-ID` 去重。
- 如果飞书存在 `邮件唯一ID` 字段，则同时进行飞书侧去重。
- 新邀请默认新增记录。
- 提醒、改期、取消或结果邮件，只有在公司、岗位、环节类型和轮次唯一匹配时才更新旧记录；否则新增记录，避免错误覆盖。
- 一封邮件包含多个独立流程事件时，会分别生成记录，并在邮件 ID 后附加事件序号。
